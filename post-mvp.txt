## 2. Ponytail full — bugs, risks, and gaps

1. **High — artifact paths permit traversal and reject valid target forms.** `ComputerName` is joined directly into local paths. A target of `..\..\escaped` resolves outside the output root, while a valid IPv6 address such as `fe80::1` throws because `:` is illegal in a Windows filename. Sanitize it into a single safe path component while preserving the original result value. `src/Private/Execution/Write-WinPushCommandOutputArtifact.ps1:300`, `src/Private/Logs/New-WinPushLogArtifactDirectory.ps1:36`

2. **High — artifact-write failures can abort all remaining targets.** Several catch paths retry the same failing writer; native script capture occurs outside its execution catch. An invalid/unwritable output path or full disk can therefore produce no result and stop fan-out. Artifact creation needs its own guarded result path and must not be retried unchanged. `src/Public/Invoke-WinPushCommand.ps1:155`, `src/Public/Invoke-WinPushScript.ps1:179`, `src/Public/Invoke-WinPushPackage.ps1:401`

3. **High — URI packages are downloaded and executed without a trust check.** Validation requires only an absolute URI; HTTP is accepted and there is no checksum, signature, or size limit before deployment to every target. Require HTTPS and support an expected SHA-256 or Authenticode validation before opening endpoint sessions. `src/Private/Execution/New-WinPushPackageStagePlan.ps1:44`, `src/Public/Invoke-WinPushPackage.ps1:249`

4. **Medium — relative remote staging roots are accepted but cleanup resolves them locally.** A value such as `.\relative-stage` is created relative to the remote session's working directory, while cleanup canonicalizes it against the controller's working directory. Cleanup consequently targets a different path. Require an absolute Windows path. `src/Public/Invoke-WinPushPackage.ps1:214`, `src/Private/Execution/New-WinPushPackageStagePlan.ps1:19`, `src/Private/Execution/New-WinPushPackageStagePlan.ps1:356`

5. **Medium — every URI invocation leaks a unique local cache directory.** The “cache” is timestamp/GUID keyed, never reused, and never removed by the command. Default use grows `C:\WinPush\PackageCache` indefinitely. Treat it as temporary storage and remove it in `finally`, unless explicit retention is added. `src/Private/Execution/New-WinPushPackageStagePlan.ps1:60`, `src/Public/Invoke-WinPushPackage.ps1:483`

6. **Medium — native commands have no configurable timeout or child-process termination.** `WaitForExit()` can block indefinitely; disposing the process object does not kill a hung WinRS/PsExec child. Add one timeout parameter at the native-process boundary and kill the process tree when exceeded. `src/Private/Execution/Invoke-WinPushNativeProcess.ps1:28`

7. **Medium — run-directory allocation is racy.** Both artifact paths use `Test-Path` followed later by `New-Item`. Concurrent controller invocations within the same second can select the same directory and overwrite logs or lose CSV rows. Include a GUID in the initial directory name or use atomic creation. `src/Private/Execution/Write-WinPushCommandOutputArtifact.ps1:289`, `src/Private/Logs/New-WinPushLogArtifactDirectory.ps1:24`

8. **Medium — the release gate does not validate real transports and is dependency-version fragile.** It runs only unit tests, which mock remoting/native boundaries, and merely checks that some `Invoke-Pester` exists while using legacy Pester parameters. Pin a compatible Pester version and add opt-in live transport gates. `build/build.ps1:29`, `build/build.ps1:54`

9. **Low — “detailed” artifact output flattens structured objects through string conversion.** Nested properties and object shape are lost in `run.log`. Use PowerShell's existing formatting or JSON when the value is non-scalar. `src/Private/Execution/Write-WinPushCommandOutputArtifact.ps1:12`

Already documented gaps include no retries, parallel fan-out, SSH, recursive/multi-target copying, script arguments, or native-transport credentials/log collection. `docs/commands.md:211`
